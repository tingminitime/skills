# 中文排版細則

`SKILL.md` 的「排版」一節列出常用規則。這份文件補上判斷方式與例外。

## 空格

- 中文與英文之間、中文與數字之間保留一個半形空格。
- 例外：百分比與度數不加空格，寫成 15%、90°。

## 標點

- 中文段落內使用全形標點符號，不用半形替代。
- 全形標點本身已包含左右留白，緊鄰標點的英文或數字不再補空格。
    - 正確：使用 React。／版本升到 3.2，測試全過。／支援三種格式（JSON、YAML、TOML）。
    - 錯誤：使用 React 。／版本升到 3.2 ，測試全過。／支援三種格式 （JSON、YAML、TOML） 。
- 括號、引號、書名號的處理相同：全形括號與其前後的中文之間不加空格，括號內部的內容依一般規則處理。

## inline backtick

以下是預設指引。使用者明確指定其他格式時，依使用者要求處理。

- 由程式碼、技術規格或工具定義的名稱、值、格式與語法使用 inline backtick。
- 引用人類語言內容時使用中文引號「」，技術名稱與概念維持一般文字。
- 依文字在句中的用途判斷：React 指產品時維持一般文字，`react` 指套件名稱時使用 inline backtick。
- backtick 內的內容視同英文，與相鄰中文之間保留一個半形空格，緊鄰全形標點時不加。
    - 正確：執行 `npm install` 之後再啟動。／設定檔叫 `tsconfig.json`。
    - 錯誤：執行`npm install`之後再啟動。／設定檔叫 `tsconfig.json` 。
- 部分 Markdown 轉譯器會替 inline code 加上內距，看起來像已經有空格。原始碼層面仍要寫出半形空格，避免不同轉譯器的呈現不一致。

## 專有名詞

- 保留原始大小寫，寫成 GitHub、TypeScript，不全部小寫或大寫。
- 不使用只有內部人才懂的字母縮寫。
- 中文情境少用的技術或專有名詞保持英文原文，例如 orphaned reference、transaction。
