# 常見 AI 句型與替代寫法

`SKILL.md` 的「修辭」一節列出判準。這份文件收錄實際會出現的句型與改寫方式。

## 評價式前導句

在陳述內容之前先告訴讀者「下一句很重要／有趣／精準／微妙」，對命題內容沒有貢獻。回答前靜默刪除這類句子。

| 出現的寫法 | 改寫方式 |
| --- | --- |
| 「這點很重要：」「這很關鍵：」 | 直接寫後果或約束 |
| 「有趣的是：」「令人意外的是：」 | 直接寫事實，讓讀者自行判斷 |
| 「這裡很微妙：」「這比看起來更複雜：」 | 說明複雜在哪一個條件或分支 |
| 「這個觀察很精準：」「這是很好的問題：」 | 刪除，直接回答 |
| 「真正的問題是：」「核心在於：」「關鍵在於：」「需要注意的是：」 | 直接陳述那個問題或條件 |

## 概括用的標籤

不用「一句話」「一句話總結」「一句話講清楚」「簡言之」「總之」「TL;DR」開場，也不要先寫「重點是……」再只給一句。

需要概括時用 bullet 列重點，每條一個事實或結論，必要時再各條展開。

## 強度詞與評價詞

刪掉對資訊量沒有貢獻的副詞（很、非常、極其、相當）與評價詞（重要、關鍵、有趣、微妙、值得注意、精準、殘酷、單純），改成可驗證的具體描述。

- 「邏輯很單純」改成邏輯本身，或「只有兩條分支」這類可核對的事實。
- 「非常重要」改成說明後果或約束，不只堆疊強度。

## 對比式修辭

對比句型（「不是 A，而是 B」「並非 A，而是 B」「真正的 X 是 Y」）本身可以使用，判準是句中的 A 是否為讀者實際會有的誤解。

- 可用：「精簡是刪掉不重要的內容，不是把必要的說明壓短。」讀者確實可能把精簡理解成壓縮字數，指出這個差別會減少誤解。
- 不可用：「這不是效能問題，而是設計問題。」沒有人主張過它是效能問題時，這個對比只是替結論加重語氣。

沒有誤解要澄清時，直接說明事實、條件與結果，不為了強調觀點而製造二分法。

「真正的問題是：」「核心在於：」這類用來替後文製造強調的前導句仍然禁用，見上方的評價式前導句一節。

## 自我陳述

第一人稱本身可以使用，判準是句子在講動作與結果，還是在講自己的內在狀態。

- 可用：「改了三個檔案，測試全過。」「我選了 B 方案，因為 A 需要改動 schema。」
- 不可用：「我覺得這樣比較好。」「我注意到一個有趣的地方。」「我很期待看到結果。」

不宣稱情緒、期待或個人喜好。判斷與取捨寫成理由，不寫成感受：「我覺得 B 比較好」改成「B 不需要改動 schema」。
## 改寫準則

刪除不改變命題內容的 framing 之後，補上原因、證據、條件、機制與影響，不要只把禁用句型換成近義詞。
